Most React applications deal with forms. Traditionally, we handle submissions with `onSubmit`.
React 19 added support for passing functions to a form’s `action` prop.
In this post, we’ll compare three approaches: plain `onSubmit`, `action`, and `onSubmit` with `useTransition`.

Throughout this post, we’ll use the following mock subscription API.
It simulates a one-second request and returns an error for `test@example.com`,
or success for any other email. All three form examples below refer to this same `subscribe` function.

```ts
async function subscribe(email: string) {
  await new Promise((resolve) => setTimeout(resolve, 1000));

  if (email === "test@example.com") {
    return {
      success: false as const,
      error: "This email is already subscribed.",
    };
  }

  return { success: true as const };
}
```

## Handling form submissions with `onSubmit`

First of all let's take a look how we would have implemented a simple newsletter subscription form using the
`onSubmit` method:

```tsx
import { useState } from "react";

export default function NewsletterForm() {
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [error, setError] = useState("");
  const [success, setSuccess] = useState(false);

  async function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();

    const form = event.currentTarget;
    const formData = new FormData(form);
    const email = formData.get("email") as string;

    setIsSubmitting(true);
    setError("");
    setSuccess(false);

    try {
      // Uses the mock subscribe() API defined above.
      const result = await subscribe(email);

      if (!result.success) {
        setError(result.error);
        return;
      }

      setSuccess(true);
      // Reset the form after a successful subscription.
      form.reset();
    } catch {
      setError("Something went wrong. Please try again.");
    } finally {
      setIsSubmitting(false);
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="email" name="email" placeholder="Enter your email" required />

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? "Subscribing..." : "Subscribe"}
      </button>

      {error && <p role="alert">{error}</p>}
      {success && <p>Successfully subscribed!</p>}
    </form>
  );
}
```

## Handling form submissions with `action`

Here is the same example written using the `action` prop:

```tsx
import { useState } from "react";
import { useFormStatus } from "react-dom";

// Track submission status to disable the button and show progress.
function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? "Subscribing..." : "Subscribe"}
    </button>
  );
}

// Show success or error messages, hiding them while submitting.
function FormMessages({ error, success }: { error: string; success: boolean }) {
  const { pending } = useFormStatus();

  if (pending) return null;

  return (
    <>
      {error && <p role="alert">{error}</p>}
      {success && <p>Successfully subscribed!</p>}
    </>
  );
}

export default function NewsletterForm() {
  const [error, setError] = useState("");
  const [success, setSuccess] = useState(false);

  async function action(formData: FormData) {
    const email = formData.get("email") as string;

    setError("");
    setSuccess(false);

    try {
      // Uses the mock subscribe() API defined above.
      const result = await subscribe(email);

      if (!result.success) {
        setError(result.error);
        return;
      }

      setSuccess(true);
    } catch {
      setError("Something went wrong. Please try again.");
    }
  }

  return (
    <form action={action}>
      <input type="email" name="email" placeholder="Enter your email" required />

      <SubmitButton />
      <FormMessages error={error} success={success} />
    </form>
  );
}
```

## Comparing `action` prop with plain `onSubmit`

As you may notice there are some changes between the two examples. Let's go through what changes when we use `action` instead of `onSubmit`.

With `action`, we don't need `event.preventDefault()` - React handles the submission without triggering the browser's default navigation.

The action receives `FormData` directly, so we don't have to access `event.currentTarget` and construct it ourselves.

### Automatic form reset

React resets uncontrolled fields when the action completes without throwing, eliminating the manual `form.reset()` call.
In our `action` example, since we handle the error without throwing, React clears the email field even when
the subscription fails. In the `onSubmit` example, we call `form.reset()` only after a successful subscription, so the email stays in the field when something goes wrong.

### Function passed to action runs in transition

Besides these, the main difference from plain `onSubmit` is that React runs the function passed to `action` inside a Transition.
This lets us use the capabilities that Transitions offer.

### `useFormStatus` and `FormMessages`

Notice that we also had to refactor the code a little to use [`useFormStatus`](https://react.dev/reference/react-dom/hooks/useFormStatus) for the loading indicator and to hide previous error or success messages while submitting using the `FormMessages` component.
When you pass a function to the `action` prop, React makes the pending state available to child components via `useFormStatus`.

State updates made at the start of the action can be deferred until the submission finishes. As a result, a manual loading flag may never appear during the request, which is why we use `useFormStatus` for the loading indicator.
An old error or success message can also remain visible while the button says “Subscribing...”, so `FormMessages` uses that pending state to hide previous messages during submission.

## Handling form submissions with `onSubmit` and `useTransition`

As we said `action` prop runs the function passed to it inside a Transition. However, we can also start a Transition ourselves
by combining `onSubmit` with `useTransition`. This hook returns `isPending` to track pending work and `startTransition` to start the Transition:

```tsx
import { useState, useTransition } from "react";

export default function NewsletterForm() {
  const [isPending, startTransition] = useTransition();
  const [error, setError] = useState("");
  const [success, setSuccess] = useState(false);

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();

    const form = event.currentTarget;
    const formData = new FormData(form);
    const email = formData.get("email") as string;

    setError("");
    setSuccess(false);

    startTransition(async () => {
      try {
        // Uses the mock subscribe() API defined above.
        const result = await subscribe(email);

        if (!result.success) {
          setError(result.error);
          return;
        }

        setSuccess(true);
        // Reset the form after a successful subscription.
        form.reset();
      } catch {
        setError("Something went wrong. Please try again.");
      }
    });
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="email" name="email" placeholder="Enter your email" required />

      <button type="submit" disabled={isPending}>
        {isPending ? "Subscribing..." : "Subscribe"}
      </button>

      {error && <p role="alert">{error}</p>}
      {success && <p>Successfully subscribed!</p>}
    </form>
  );
}
```

Here we clear the previous error and success messages _before_ calling `startTransition`, so they disappear immediately
(they are not deferred as in the example with `action` prop so we don't use the `FormMessages` component).
We use `isPending` for the loading indicator and don't need `useFormStatus` in this example.

There is another difference now between using `action` prop and `onSubmit` with `useTransition`: progressive enhancement when working with Server Functions.
With `onSubmit`, our submission handler runs on the client, meaning JavaScript must be loaded and the component hydrated before the handler can execute.
On the other hand, when we pass a Server Function to the action prop, React can support form submissions even before JavaScript has loaded. For example,
in Next.js, a form rendered by a Server Component can submit directly to the server using the browser's native form submission mechanism, even when JavaScript is disabled.
This is something that `onSubmit` combined with `startTransition` cannot provide.

## Next: `useActionState`

There is also another option of working with the forms which works with the `action` prop: [`useActionState`](https://react.dev/reference/react/useActionState).
It returns the action's result as state and exposes an `isPending` flag, so we don't need separate `useState`
calls or a `useFormStatus` child component. This is a topic maybe for another post.

## Notes

These examples use uncontrolled inputs, so their values are not stored in React state. All three approaches also work with controlled inputs.
With controlled inputs, we would manage the email with `value` and `onChange`, could read it from state instead of `FormData`, and would clear it
with `setEmail("")` rather than `form.reset()` or the automatic reset from `action`. Automatic resets only apply to uncontrolled fields;
the pending-state and Transition behavior discussed above stays the same.
